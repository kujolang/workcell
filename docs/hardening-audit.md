# Workcell hardening audit

Date: 2036-07-11

The audit reproduced four defects before fixes. Each now has a regression test:

1. Partial nested definitions passed validation and then crashed when summaries or policies read a missing field. `resolve_definition` now fills nested defaults before validation.
2. Newly created binary files were reported as `binary: false` in `changes.json`, even though the generated patch contained binary data. Untracked files now use Git's binary-aware no-index numstat detection.
3. Image-preparation failures returned JSON `exit_code: 4` but the launcher process exited `3` unless the error text happened to contain the word `docker`. The CLI now honors the structured result code.
4. An empty declared secret caused log redaction to replace every string boundary, corrupting captured logs. Empty secret values are now skipped by the redactor.

Additional hardening completed in this pass:

- Nested default filling is centralized in one helper instead of repeating field-by-field logic at each call site.
- Host-control environment policy is centralized and now rejects proxy, Git credential-helper, GitHub, npm-token, and existing Docker/cloud control variables.
- Docker-built image resources now carry Workcell ownership, run ID, project, and version labels for auditable resource boundaries.
- Binary change classification indexes Git's binary paths before updating file metadata, and untracked files use batched MIME probes in bounded chunks rather than one probe per file.

Iteration 062 specifically verified that workspace scans return the depth actually observed and reject file entries beyond `max_depth`, avoiding both misleading telemetry and a file-depth limit bypass.

Iteration 063 added fail-closed API-boundary validation for workspace strategies, cleanup strategies, run identifiers, and non-string CLI tokens. The current totals are 191 Workcell, 27 workspace, and 7 stress assertions.

The follow-up hardening pass also added declarative verification containers, bounded artifact export policies, host-mapped workspace ownership, bounded workspace scans, image ID/platform/label provenance, `clean --dry-run` inventory with explicit image retention, a first-class verification example, version-source validation, a compatibility matrix, and a 2,000-file opt-in performance signal.

The continuation review caught and fixed two additional concrete failure paths: human-readable failure output attempted to concatenate a null patch path after early failures, and a workspace scan could race with disappearance between directory discovery and listing. Both now fail with stable fallbacks and regression coverage; empty orphan Workcell directories are safely recoverable while non-empty unowned paths remain preserved.

The OCI continuation review found one additional concrete security gap: Podman preparation and doctor checked rootless mode but did not require Podman's seccomp profile to be enabled. Both paths now inspect `Host.Security`, fail closed when `seccompEnabled` is false, preserve AppArmor absence as an explicit rootless warning, and have a fake-CLI regression contract plus live Docker/Podman OCI evidence.

The filesystem-boundary continuation reproduced two more concrete runtime failure paths. Workspace scans and recursive artifact scans previously allowed permission errors from `list_dir` or `file_size` to escape as Kujo VM crashes. Both now return structured failures, artifact output directories are required to be prepared successfully, and permission-denied workspace/artifact regressions cover the behavior.

The artifact and evidence continuation reproduced five contract defects: duplicate or overlapping artifact declarations could double-copy content and make redaction order-dependent, verification command names could collide in machine-readable results, and manifests accepted duplicate entries or omitted files when totals were forged. Export validation now rejects duplicate/overlapping declarations, verification names are unique, and manifest verification requires a complete, unique file set matching the run directory.

The runtime inventory continuation reproduced a Docker CLI contract defect: combining `docker ps -q` with `--format` discarded the formatted container names, so dry-run inventory could not support reliable incident-response identification. Inventory now keeps the compatible container-ID list, performs a correctly formatted detail query, and exposes additive `container_details[]` records with stable IDs and names; Docker integration coverage proves active labeled resources remain visible and preserved.

The next continuation review reproduced two more concrete failure paths. `inspect` assumed policy construction always succeeded, so host UID/GID resolution failures could crash human output or return success in JSON mode; inspection now returns a structured failure and exit code 3, with a fake-`id` CLI regression. Verification startup failures returned without attempting to stop/remove a potentially created labeled container; verification now performs idempotent cleanup attempts and records the cleanup status, with a fake-Podman contract proving `run`, `stop`, and `rm` are all attempted. The same review also found that cloud credential and runtime-selector variables were not in the host-control environment deny list; those names are now rejected with regression coverage.

Iteration 060 reproduced four additional lifecycle/security defects. Direct cleanup and empty-orphan recovery trusted a symlinked `.owner` marker, so a target file containing a matching marker could authorize deletion; cleanup now rejects marker symlinks and inventory reports `marker-symlink`. Runtime removal treated Docker/Podman “no such container” responses as failures even though cleanup is idempotent; those responses are now successful and have a fake-runtime contract. A null output request was silently converted to the default output root instead of being rejected; coordinator input validation now fails closed. Finally, a container startup rejection was recorded with result stage `failed`, causing the CLI to return internal-error code 10 instead of the documented startup code 5; the result now uses the `starting` stage when cleanup succeeds and a dedicated startup-failure contract proves code 5, receipt code 5, and complete cleanup.

Iteration 061 reproduced a cleanup portability defect: `stop_container` matched `No such container` case-sensitively and did not recognize the lowercase/wording variants emitted by different Docker and Podman versions. Stop cleanup now normalizes the message and accepts `no such container`, `no container with`, `container not found`, and `is not running`; the fake-runtime contract exercises all three missing-container variants for both stop and remove.

The manifest/receipt/cleanup continuation reproduced three additional concrete failure paths. Integrity-manifest collection crashed on inaccessible child directories, receipt creation crashed while hashing an unreadable definition file, and stale-workspace cleanup crashed while inspecting an inaccessible orphan. Manifest collection/verification, receipt hashing, and stale-workspace root/orphan listing now fail closed with structured errors and preserve unsafe paths; regressions cover each case.

The load continuation added a bounded deployment matrix for concurrent runs. Four simultaneous Docker and rootless Docker/Podman executions preserved unique run IDs and source immutability, verified manifests/artifacts, and cleaned every successful workspace and container; larger production load profiles remain deployment-owned.

The CLI continuation found a concrete correctness gap: `--help` and `--version` were not recognized globally, and options intended for another command or extra positional arguments were silently ignored. The parser now supports global help/version, validates command-specific options, rejects extra positionals with exit code 2, and exposes the global options in `workcell-cli/v1`; CLI smoke coverage exercises all paths.

The artifact review found a concrete secret-safety gap: non-text artifacts were silently allowed through `reject`/`redact` secret policies because unreadable files were treated as clean. Secret-aware artifact export now fails closed when a declared secret cannot be inspected, and the contract suite covers a binary secret fixture.

The definition resolver also had a concrete malformed-input crash: a `network: null` section was indexed before validation could report its type error. Network default expansion now runs only for object sections, and the contract suite confirms malformed network types return validation errors without a runtime exception. Artifact redaction now carries its relative path through recursive traversal so write failures cannot reference an undefined local.

The timeout parser had a second malformed-input crash: oversized duration strings could throw during integer parsing or millisecond conversion before validation returned. Both parsing and multiplication are now guarded, and overflow-duration regressions fail with structured validation errors.

The numeric resource validators had the same malformed-input crash class: oversized UID/GID and memory strings could throw during integer parsing before validation returned. Identity and memory parsing now fail closed with structured validation errors, and overflow regressions cover both paths.

The release-report renderer had the same issue when an evidence directory contained a malformed numeric exit or metric file. Report parsing now falls back to safe sentinel values and marks the affected suite unsuccessful instead of crashing; the report contract covers oversized metric and exit values.

The opt-in performance harness also accepted a caller-controlled `WORKCELL_PERF_FILES` value without guarding integer parsing. Oversized values now fall back to the bounded default fixture size, and the standard run exercises that malformed environment path.

Verification on the local Docker/Colima daemon passed the full offline suite and `tests/docker_integration.sh`; rootless Docker and rootless Podman in the Colima Linux VM also passed the OCI, full integration, and egress suites. The integration run covered successful execution, declared artifacts, controlled edits, runtime image builds, digest verification and mismatch failure, workload failure, timeout cleanup, symlink rejection, and ownership-scoped cleanup. Docker buildx 0.35.0 is installed locally and the integration suite now exercises BuildKit.

Remaining enterprise-grade recommendations are rootless or microVM daemon deployment, a controlled egress proxy, and key lifecycle/transparency policy around cosign. Workcell now accepts reviewed named seccomp/AppArmor profiles and pre-created custom networks, rejects arbitrary absolute output destinations, redacts secret literals incrementally in stream logs and completion outputs, records cancellation explicitly, and classifies Docker exit 125 correctly, but does not install profiles or provision the daemon. CI now runs on a clean Docker runner, and BuildKit is required in CI with a local legacy-builder fallback.
